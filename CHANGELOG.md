# Changelog

## Unreleased

## 0.2.2 — 2026-11-15

- Fixed: move preflight correctly classifies missing sources and non-directory destinations on Windows.

- Fixed: Worktrees shows a submodule’s actual working folder instead of its Git metadata directory, including when viewed from a linked worktree. Repositories with a separate Git directory also show the correct folder when opened directly.

- Fixed: errors from applying a clipboard patch remain visible after the Git workspace refreshes.

- Fixed: the Git Worktrees sidebar discards responses from previously selected repositories, and its `d` and `n` shortcuts respect the Vim keys setting.

- Fixed: with *Calculate automatically* on, folder sizes are also refreshed after undo, moving to the trash, restoring from the trash, a folder sync and F5, also for a listed subfolder.

- Fixed (Windows): mapped network drives such as `W:` and `X:` now appear in Drives. Enumeration does not query remote capacity or volume labels, so these rows have no space bar.

- Fixed: dropdown menus use the active Gall theme for their background, text, groups and highlighted choice instead of the desktop’s native menu colours. Keyboard selection, type-ahead and Escape remain available.

- Fixed: structural comparison preserves significant spaces in shell backslash escapes, Lua long bracket strings and INI-style configuration values (including `.properties`). These edits count as changes and remain reachable with next/previous change in the compare view. See [comparison usage](README.md#highlights).

- Structural comparison conservatively retains whitespace in prose, YAML, markup and JSX/TSX, shell files with heredocs, C preprocessor directives and JavaScript lines after an ambiguous slash. C-family files with raw strings, text blocks or continued directives use literal comparison. Explicit CRLF/LF comparison remains literal. Switching Git files clears token marks for the previous language immediately. See [comparison usage](README.md#highlights).

- New: diffs are structural. The compare view and the Git diffs (Working Changes, commit details) compare changed code by its tokens (words, operators, brackets, strings, comments) instead of whole lines, so reformatting is not a change: a call split over several lines, new indentation, aligned columns or blank lines show dimmed with `≈`, are not counted and are skipped by next/previous change, and only the tokens that really changed are marked. Gall uses language-specific token rules for common source files (Rust, C and C++, Java, JavaScript and TypeScript, Go, Python, shell, JSON, CSS, SQL and more); where whitespace means something (inside strings, Python and YAML indentation, a line break that ends a statement) it stays a change, and in files of an unknown type every space counts. In the compare view `t` or the `{}` button switches back to the plain line diff. Git diffs are read hunk by hunk, so a hunk that starts inside a comment or a string spanning lines is read as code.

- Fixed: Git Working Changes and the history graph show staged submodule pointers and embedded repositories, including a newly staged `.worktrees` folder. They no longer report Clean while these changes block rebase. The rejection identifies the affected paths; unstage and locally exclude an unintended folder before retrying, without deleting its contents.

- Fixed: ordinary rebase now works in repositories with submodules. It rewrites the parent repository while leaving submodule checkouts, local edits and untracked files untouched, including when Git is configured to recurse into submodules. Continue, Skip and Abort also leave those folders alone.

- Improved: opening a folder with very many items is several times faster. What Gall reads about each item is now read on several threads (a folder of 46 500 items lists in about 70 ms instead of 290 ms on Linux with 8 cores), and the folder is no longer opened item by item when Gall starts watching it for changes, which on Windows and macOS took longer than the listing itself in folders such as `AppData`. Saving the session no longer delays a navigation: it is written in the background (and before the app exits), not before the folder is asked for.
- Improved: finding files by name walks the folders on several threads and no longer builds a lower-case copy of every name (60 000 files in about 30 ms instead of 260 ms).
- Improved: syntax colours in the compare view appear about ten times sooner for long files (40 000 lines in 0.5 s instead of 5 s, after which the rest stayed plain): the text is coloured in pieces on several threads, and a piece is kept only when it is exactly what a single pass would give.
- Improved: the notes Gall keeps for a bug report are sent to the backend together instead of one message per command, which halves the traffic between the window and the backend.
- Improved: Gall starts without waiting for the history, the drives and its listeners one after the other, so a history entry on a network share that does not answer no longer keeps the window on "Loading…"; the query for how Gall was installed (bug report) runs after the window exists.
- Improved: the window no longer freezes while settings, favourites or folder marks are saved, while "Open with", "Reveal" or a terminal start, or while colour tags are read: these run in the background. Settings are saved after a pause in typing instead of on every keystroke, and the drive list is not polled while the window is hidden.
- Improved: colour tags stay fast with very many tagged files (tagging 1 000 files takes 1 ms instead of 36 ms with 100 000 tags, renaming 200 tagged files 5 ms instead of 2.5 s).
- Improved: deleting, and moving within one drive, start at once instead of first counting every file in the folders involved.
- Improved: zip archives with very many files open about three times faster (50 000 entries list in about 110 ms instead of 330 ms, one file inside opens in about 190 ms instead of 650 ms). A zip with a damaged entry is now listed and reports the error when that entry is opened.
- Improved: opening or previewing a file inside a 7z archive decodes only the block that holds it, up to that file, instead of the whole archive; inside a tar archive (also compressed) reading stops after the file instead of at the end of the archive. Going back to an archive opened earlier no longer reads its list again: Gall keeps the lists of the 32 archives used last instead of forgetting all of them after 16.
- Fixed: folders with more than about 120 000 items no longer fail to show because of the column-width calculation, and the name-search result list renders each row once.

- Improved (Windows, WSL): Git actions start fewer Git processes, one after the other. Creating or deleting a branch takes about 130 ms instead of 230–290 ms (the branch name is checked by Git's documented rules and the branch looked up in Git's files), the conflict check of the history editor replays the whole plan in one `git merge-tree --stdin` instead of one process per commit (about 45 ms instead of 380 ms for ten commits), and committing, cherry-pick, checkout, fetch and push check the repository with side-by-side instead of serial queries. A branch switch on Windows writes its files with Git's parallel checkout. For repositories inside WSL the Git workspace is up to 2.5 times faster: the history graph of a linked worktree or submodule opens in about 0.1 s instead of 0.3 s, and the main graph, Tools and the actions take 130–240 ms. Gall now checks the markers of a running merge or rebase with one listing of the Git directory (looking up a missing file through `\\wsl.localhost` takes about 25 ms), reads the changed files' sizes and times through the shell already running in the distribution instead of starting `wsl.exe`, and keeps up to 16 of those shells. Stash, merge, rebase and push on native Windows remain slower than this (0.4–0.8 s in a 25 000-file repository) because of Git's own work there.
- Improved (Windows): the Git workspace opens and refreshes about twice as fast on Windows, where every Git process costs 40–80 ms. Gall reads HEAD, branches, tags and the stash list from the files Git keeps instead of asking Git, reads a whole work tree with one `status` instead of two processes, compares changed files side by side and starts the remaining Git queries in parallel. With 50 000 files and 20 000 commits the repository snapshot takes about 140 ms instead of 400 ms, the history graph 150 ms instead of 430 ms, Working Changes 100 ms instead of 270 ms, Tools (worktrees, submodules, bisect) 160 ms instead of 560 ms, and staging a file 140 ms instead of 330 ms; fetch, checkout, commit and branch actions are about a third to a half faster. Gall still asks Git whenever the files are ambiguous (reftable, symbolic branches, environment overrides, repositories inside WSL).
- Fixed (Windows): WSL Git commands no longer forward unset environment variables as empty values. Fetch and push could fail with "transport 'file' not allowed" because an absent `GIT_ALLOW_PROTOCOL` became an empty allowlist. Explicit protocol restrictions and the user's WSL forwarding settings are preserved.
- Improved: Git is much faster everywhere, most of all on Windows and for repositories inside WSL, where every Git process started costs tens of milliseconds. Moving between folders of a repository now starts one Git process instead of five or six (the badges, the branch in the status bar and the "Git blocked" check), also inside ignored and hidden folders such as `node_modules` or `.cache`. In the Git workspace, Working Changes read the repository once instead of up to four times (16 processes down to 4, about 2.5 times faster), the selectable patch of a file takes 7 processes instead of 28 (three times faster), Tools (worktrees, submodules, bisect) no longer load the whole repository twice, and clicking through the files of a commit starts one process per file instead of six or seven. Gall now reads the work tree root, the Git directory and the markers of a running merge or rebase from the files Git keeps, and asks Git for the content filters only when the configuration changed. The status of a whole work tree is read by two Git processes side by side (tracked changes and untracked files) instead of one after the other, which makes it about a third faster in a large repository.
- Improved: the history graph, the history of a file and blame are several times faster in repositories with a long history (about 40 ms instead of 230 ms for the graph of 20 000 commits, blame 55 ms instead of 170 ms). When a history view opens, Gall writes Git's commit-graph with changed-path filters in the background if the repository has none or an old one (`git commit-graph write --reachable --changed-paths`, the index `git gc` and `git maintenance` keep). It changes no commit, branch or file of the work tree; delete `.git/objects/info/commit-graph` to remove it. The history of a file follows renames without `git log --follow`, which read every commit (25 ms instead of 600 ms there), and the plan of the history editor is read in one query instead of one per commit.
- Improved: merge, rebase, cherry-pick, stash, commit, branch and checkout actions in the Git workspace start a third fewer Git processes: the checks before an action (clean work tree, nothing unmerged, no submodules, where HEAD is) reuse what the stale-state check just read instead of asking Git again, and a checkout no longer loads the history graph first.
- Improved: in a work tree that was just cloned, checked out or added with `git worktree add`, status is up to 2.5 times faster. Git cannot tell from its index whether files written in the same moment as the index changed and compared their content on every status, because Gall never wrote the index. Gall now lets Git refresh the index in the background when a Git view opens (`git update-index --refresh`, what `git status` in a terminal does), with hooks off and not in repositories with content filters.
- Improved: folders with many hidden items (a home folder) list faster when hidden items are not shown: a name with a leading dot is skipped before anything is read about it.

- Improved: deleting a local branch that has commits no other branch contains (Git: "not fully merged") no longer just shows Git's error. Gall asks again, names the branch tip so it can be recreated, and on **Force delete** runs `git branch -D`, as lazygit does.
- New: a remote branch can be deleted from the Git workspace. Select it in the **Remote branches** list (or its row in the history graph) and press `d`, or use **Delete branch…** in its context menu; after a confirmation Gall runs `git push <remote> --delete <branch>` on the branch's own remote and the tracking reference disappears. Before, `d` worked on local branches only. The command is now simply **Delete branch…** for both kinds.
- New: a stash can be applied, popped or dropped straight from the history graph. Right-click a stash row (such as `refs/stash` · "On Dev: …"), or press the Menu key or `Shift+F10` on it, to get **Apply stash…**, **Pop stash…** and **Drop stash…** instead of the history-rewriting actions that cannot work on a stash. With Vim keys, Space, `g` and `d` on a stash row apply, pop and drop it like in the Stashes tab. Dropping still keeps a recovery reference.
- Fixed: switching branch or checking out a commit in the Git workspace of a repository with submodules failed with "Switching repositories with submodules is not supported yet". It now works like in lazygit or GitLens: the switch never changes a submodule's folder, so edits and untracked files inside a submodule do not block it. A submodule whose checked-out commit differs from the new branch's record shows as modified; update it in Tools → Submodules when needed.
- New: like GitLens, the history editor (interactive rebase) tells you at once which commits would conflict. Every time you move a commit or change its action, Gall replays the plan in memory (`git merge-tree`; no file, index or branch changes) and marks each commit that would stop the rebase with **Conflict** and the files involved, with a conflict count (or "No conflicts") in the header. After a conflict the check goes on as if it were resolved, so later commits may be flagged too. It needs Git 2.40 or newer; with an older Git the editor works without the check.
- Fixed: in a repository with submodules, Continue, Skip, Abort and conflict resolution of a rebase stopped in the Git workspace failed with "Worktree operations with submodules require the terminal", so a rebase started in Gall could not be finished or aborted there. These steps now work with submodules; starting a merge, rebase, cherry-pick, revert or reset still does not.
- Improved: in the Git workspace the commit copy menu (`y`) opens at the click when it comes from the context menu, and level with the commit row, right of its text, when it comes from the keyboard, instead of below the row over the commits that follow. With Vim keys on each entry shows its key (`y` hash, `i` abbreviated hash, `s` subject, `b` body, `m` full message, `a` author, `e` date, `u` URL, `d` diff, `t` tags) and pressing it copies.
- New: like GitLens, a commit's patch can be copied and pasted. **Commit patch** (`y` then `p`) puts the commit on the clipboard as an email-style patch (binary files included; merge commits and patches above 16 MiB are refused), and **Apply patch from clipboard…** (`a` on the commit list, or the commit context menu) checks it against a clean repository, asks, and applies it to the index and working folder without creating a commit. The Tools → Patches tab still exports and applies patch files.
- Improved: the history editor (interactive rebase) works in repositories with submodules instead of refusing with "Interactive rebase with submodules requires an external Git client". A rebase never changes a submodule's folder, so edits and untracked files inside a submodule do not block it; a submodule checked out at a different commit than the repository records still counts as a local change to commit or stash first. When the rebase finishes, Gall names the submodules whose folders no longer match the rewritten history so they can be updated in Tools → Submodules.
- Fixed: the Git workspace's working changes loaded with "A changed path is not a regular file or symlink" when an untracked nested repository (a folder with its own `.git`) was among the changes; they now load. For a repository in WSL the stale-state check also reads the changed files with one `stat` inside the distribution instead of file by file over 9P, so a large number of changes loads faster.
- Fixed: after a history rewrite succeeds (reword, amend, drop, squash, fixup, move, interactive rebase, also after continuing or aborting a rebase) Gall removes its `refs/gall/recovery/<previous HEAD>` reference, so it no longer shows up in other tools' graphs. It stays when the rewrite fails or stops for a conflict or an edit, and discard, reset and detached-HEAD recovery references are unchanged. The previous commit is still reachable through the reflog.
- Fixed (Linux): files with the execute bit run when opened (Enter, double click), as in Dolphin, instead of nothing happening or opening in the wrong program: AppImages and native programs start directly, scripts with a `#!` line run in a terminal (the configured one, else the first installed) and wait for Enter so their output stays visible, and `.desktop` launchers start through `gio launch`. They were handed to `xdg-open`, which only looks at the MIME type. Files without the execute bit open as before, so a script is previewed or edited until it is made executable.
- Improved: the repository selector of the Git workspace (opened repository and its submodules, also nested ones) is a menu in the style of the other menus instead of a native list: tree guide lines, icons per level, a main badge, a note on submodules that cannot be opened, and keyboard control (arrows, Home, End, Enter, Esc, and j/k with Vim keys).
- Improved (Windows): Git for a repository inside WSL (\\wsl.localhost\...) runs inside the distribution instead of through Windows over the slow 9P file server: the Git button and badges, the history graph, diffs, branches, stashes, worktrees, submodules, fetch, pull and push. Git commands there are served by a shell that stays open in the distribution (it ends after 30 s of idleness), so the Git button and badges update in about 50 ms and the history graph with its submodule list opens in about 0.3 s (it took 2 s, and 30 s for the first status). Git then runs as the owner of the files, so "dubious ownership" does not occur, and submodules in WSL are listed as usable. Fetch, pull and push use the Git, SSH keys and credentials of the distribution, as in a terminal there. Interactive rebase still runs through Windows Git. Submodules (all platforms) are listed with about half the Git processes (one config call, one call for each submodule's work tree and HEAD) and side by side, so a project with ten submodules lists them in about 0.3 s instead of 0.6 s, and the changed-file fingerprint of a large untracked folder is read inside the distribution.
- Fixed: a Git repository that Git refuses as owned by another user (a WSL folder opened from Windows, a network share) no longer hides the Git button silently: the status bar shows "Git blocked", and a click (or gr with Vim keys) offers to trust that repository by adding it to Git's global safe.directory.
- Improved: icon-only buttons (Git help `?`, close, refresh, add, hunk select, colour tags, folder and detail toggles) show a tooltip, and choice buttons in dialogs show their key next to the label, for example `Soft (s)`, `Mixed (m)`, `Hard… (h)`. With Vim keys on, the Git merge, Git changes, Git window and commit details buttons show their key too.
- Improved: error notifications for everyday conditions (no permission, name already taken, file in use) no longer offer "Report a bug"; it stays for unrecognised errors.
- Improved: a push that Git rejects because the branch diverged (after a rebase or reset) asks, like lazygit, whether to force push with lease; Enter confirms, Esc cancels, and the Git output stays in the panel.
- Changed: macOS is no longer labelled experimental. The Rust and UI test suites run and pass on macOS, including the randomized undo test.
- Fixed (macOS): undo of a delete and of a replaced item, and the Trash window (list, restore, delete, empty), work. Gall now moves items to the Trash itself and remembers where each went, so it needs neither Full Disk Access nor permission to control Finder. The Trash window lists what Gall deleted, not items other apps put there.
- Fixed (macOS): when started from Finder or the Dock, Gall finds Homebrew and other tools on the user's `PATH` (Git, editors, terminals).
- Fixed (macOS): names stored decomposed (NFD, for example "c" + a combining caron) are found by the quick filter, search and Quick Open when typed composed or without accents, sort next to composed names and keep their Git badges.
- Fixed (macOS): the title bar shows the traffic lights on the left, shortcut hints say Cmd and Option instead of Ctrl and Alt, copying keeps Finder tags, comments and other extended attributes, and a copy into a folder is not mistaken for a different item when only the letter case differs.
- Improved (macOS): network shares and system volumes are skipped when indexing, and folders opened from Finder ("Open With", the Dock icon) open in the running window.
- Fixed: the UI test for the Alt key in Vim mode no longer fails on a Mac (Node reports a Mac platform there); the tests now run as on Linux.
- Changed: the Windows portable zip no longer contains the `portable` marker, so settings and data live in the user profile (`%APPDATA%\gall`) like in every other build and survive unzipping a new version elsewhere. Create an empty `portable` file next to `gall.exe` to keep everything in `UserData` as before. AppImage, deb and rpm already use `~/.config/gall`.
- Changed: new installations start with the breadcrumb bar instead of Miller columns and sort by date modified, newest first.
- Fixed: entering a folder selects its first item, so the cursor is visible at once instead of appearing only after the first `j` or `k`.
- Fixed: after an update the next start says "Update successful" instead of offering to report that the previous session did not close normally.
- Fixed: the bug report window keeps its height while you type in "What happened?".
- Fixed: drop-downs and number fields in Settings follow the theme on Linux (no native bevelled select, themed option list, no cramped spinner buttons).
- Improved: dragging files out of 7-Zip into Gall (which 7-Zip only supports for targets that copy during the drop, like Explorer) explains that and suggests Extract, instead of failing with "Cannot stat 7zE…: it does not exist".
- Improved: dropping items that carry no file paths (for example files dragged straight out of an archive manager) explains that they must be extracted first instead of doing nothing.
- Fixed: `gr` outside a Git repository shows a warning instead of opening an empty Git window.
- Fixed: a hard reset is no longer refused because the repository has untracked or ignored files (build output, dependencies); only files the target commit would overwrite block it, and untracked files are left alone like `git reset --hard` does.
- Improved: the recovery copies Gall makes before discarding changes or a hard or mixed reset are kept as references under `refs/gall/recovery/` (with a reflog message), not as entries in the stash list, so other Git tools no longer show them.
- Improved: the Git window is much larger (up to 1800 px wide, 95 % of the height) and the commit message column gets the room, so messages next to branch and tag labels stay readable (remote tags that duplicate a local tag are no longer drawn twice). The commit list takes 70 % of the height while it has focus and 30 % while the details have focus; the inspected commit stays centered in the list while the details have focus.
- Improved: closing the Git window asks for confirmation only when it holds unsaved work (conflict choices, manual edits, a rebase plan). `Esc` and `q` first leave Details, Working Changes, Tools or Rebase for the commit list, then close the window.
- Improved: tags (and other references) are listed newest first. The repository selector lists submodules of submodules as an indented tree, with marks for the repository (◆), submodules (◇) and nested submodules (◈), and loads much faster. The reset dialog shows its keys (`s` soft, `m` mixed, `h` hard).
- Improved: the Git sidebar tells local and remote branches and tags apart and shows which local ones are on the remote (✓ in sync, ↑↓ differing, `upstream gone`, `not tracking`, `local only`, `differs from remote` for tags). Remote branches and tags that already have a local copy are hidden by default; **show anyway** lists them.

- Improved: scrolling and moving the cursor are smooth on computers without a fast graphics card (remote desktop, virtual machines, older integrated graphics) at 100 % display scaling. The file list, the Miller columns, the sidebar, the `?` keyboard sheet, Quick Open, find in files and the compare views were drawn again in full on every scroll step; they now scroll as a layer (measured without a GPU: 14 times less drawing work in the file list).
- Improved: the `?` keyboard sheet opens about three times faster (its columns are no longer balanced by the layout engine), and windows opened over the application no longer blur what is behind them, which stalled scrolling inside them; the background is still dimmed.
- Improved: folders open faster. Listing a folder no longer asks the system about every item a second time (a folder of 3,000 files lists in under half the time on Windows), and the Miller columns skip plain files without reading anything about them.
- Improved: the record of recent actions kept for bug reports is written to disk every two seconds instead of after every single command, which blocked the window for a moment each time; errors are still written at once.

## 0.2.1 — 2026-11-11

- Fixed: the **Load more commits** button in the Git graph was almost invisible (grey system button with accent-coloured text). Every button now gets the application's button look, and faint, success, warning and danger text meets the 4.5:1 contrast ratio in the dark and light themes.
- Fixed: a video opened in the preview window has keyboard focus at once, so `k`, the arrow keys and `[` `]` work without clicking the player first.
- Fixed: video and audio previews on Linux failed with "format or codec not supported" for every file, even with all codecs installed (WebKitGTK cannot play media from Tauri's `asset://` scheme). Media now plays from a small local server that only listens on the loopback interface and uses a random token in every address.
- Added: STL files preview as a 3D model, in the details pane and the preview window: drag to rotate, wheel to zoom, double-click to reset.

- Added: Vim folder marks. With Vim keys on, `m` and a letter remembers the current folder, `'` and the letter opens it again, `` ` `` and the letter also selects the item that was focused when it was marked, `''` returns to the folder before the last jump and `d m` and the letter deletes a mark. Lower- and uppercase letters are separate marks, all of them are kept between sessions, and the which-key popup lists them with their folders. A mark whose folder is gone offers to delete it.
- Changed: with Vim keys, the colour tag is now `c` (was `m`, which now sets a folder mark), and columns ⇄ breadcrumbs is `Space w c` (`` ` `` now goes to a mark). Menus, tips and the `?` sheet no longer offer a plain key that Vim keys take over.

- Improved: the whole application now uses the look of the Git workspace. Buttons, dialogs, menus, tabs, badges, notifications, the quick filter and the selection in every list share the same rounded corners, raised buttons, gradient main action and fading accent selection with a bar on its left. Custom themes keep working; the rounding and the shared button, selection and bar styles are variables a theme can change (see [themes](docs/themes/README.md#size-and-shape)).

- Improved: in find in files, `Tab` switches the scope between the folder, Home and the whole drive (`Shift+Tab` goes back), as `Tab` does in Quick Open; both windows show `Tab` as a key next to their scope buttons. See [find text inside files](README.md#-find-text-inside-files).
- Fixed: with *Calculate automatically* on, folder sizes are refreshed after a copy, move or other file task finishes, also for a listed subfolder that received new files.
- Improved: the `?` keyboard sheet now also lists the keys of find in files, Quick Open's Enter variants, the preview window's zoom and video keys, Open with, the compare views, new-folder and rename dialogs, `q` to close windows, mouse gestures, drag & drop and bug-report clips. Tips & tricks cover the Git workspace, folder marks, batch rename, folder sizes, title-bar panel controls, favourites groups, the Trash window and more, and the README describes every feature (see [everything else](README.md#everything-else)).
- Fixed: the welcome setup said the layout is switched from the sidebar (it is the title bar), and several hints named keys that differ by keyboard profile (`F4` edit, `F2` rename, `` ` ``, `Ctrl+U`, `O`).
- Added: a [Fedora COPR repository](https://copr.fedorainfracloud.org/coprs/gama87/gall/) (`sudo dnf copr enable gama87/gall && sudo dnf install gall`), updated automatically with each release.

- Improved: the Git workspace opens and refreshes several times faster (about a quarter of the previous time on Windows), and Git status badges in the file list arrive sooner. Gall now starts the real Git program directly instead of going through launchers on `PATH` (Git for Windows' `cmd\git.exe`, Scoop shims), reads HEAD, remotes and the configuration with fewer Git processes, and runs the remaining queries side by side.

## 0.2.0 — 2026-11-09

- Fixed: on Windows, cloning a repository and creating a worktree no longer fail with "could not open … .git/HEAD" (the destination was passed to Git as a `\\?\` path).
- Fixed: WezTerm is started as a new process, so "Terminal here" no longer asks an already running WezTerm (for example on another desktop) to open the window, which produced empty windows and needed a second keypress. A terminal command you saved earlier keeps its old text; edit it in Settings › Window or choose the terminal again with Ctrl+Enter.
- Fixed: Linux packages (deb, rpm, AppImage) now declare Gall as a handler for folders (`inode/directory`) and as a file manager, so it appears in the File manager list of Plasma's Default Applications and can be chosen for Meta+E.
- Improved: the commit context menu in the Git workspace now offers **Rebase current branch onto this commit…** (under Rewrite history) and **Merge this commit into current branch…** (under Integrate), as in Git Graph and GitLens. They have no key on a commit because lazygit has none there (rebase is `r` and merge `M` on a branch, `b` opens bisect options); commit-panel keys follow lazygit.
- Improved: Git workspace menus have one job each. Right-click, `Shift+F10`/Menu key or a row's **⋯** button opens the menu of that commit or reference; the toolbar **Actions** button holds repository-wide actions (fetch, pull, push, force push with lease, stash, refresh, search, terminal, continue/skip/abort). The separate "Panel actions…" button is gone, because **+** already creates items.
- Improved: the Git workspace footer shows the keys of the focused panel (like lazygit's options bar) and how to move around: `h`/`l` move between the sidebar, the commit list (with Working Changes as its first row) and the details, `[`/`]` switch sidebar tabs, and `Esc` returns to the commit list (also from Working Changes). An unsent commit message is kept when you leave Working Changes and come back. The panel with keyboard focus is outlined and named in the footer (Commits, Branches, Commit details, Working Changes), and the selection in the other panels is shown muted.
- Improved: in the Git workspace `y` on a commit opens lazygit's copy menu (hash, abbreviated hash, subject, message body, full message, author, date, commit URL for GitHub, GitLab, Bitbucket and Codeberg remotes, whole-commit diff, tags). `l` or Enter opens the commit details, `b` opens the tools on bisect options, `w` on worktree options and `x` the repository tools (as in lazygit, `b` and `w` are bisect and worktree options); `Esc` or `h` returns from the tools to the commit list.
- Fixed: Git workspace refreshes no longer freeze while a fetch, push or clone is running. Long transfers are stopped only after three to five minutes without output (instead of a fixed total time), and a failed or cancelled clone removes the folder it created so the same path can be used again.
- Fixed: Git workspace tools no longer refuse repositories that only use the standard Git LFS filters (switching, pulling, interactive rebase and worktrees work again). A stale saved rebase plan no longer blocks later rewrites or leaves leftover plan folders, and cancelled remote jobs are always unregistered.
